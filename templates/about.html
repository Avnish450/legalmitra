About this Project

LegalMitra is a second-year engineering mini project: a legal information portal with a voice-enabled AI chatbot, built from scratch in Python and plain HTML, CSS and JavaScript.

The idea

Most people meet the law only when something has already gone wrong — a cheque bounces, a landlord refuses a deposit, a salary is not paid, a builder delays a flat. At that moment they face two problems at once. First, they do not know which branch of law their problem belongs to. Second, everything written about it is written for lawyers.

We wanted to build the thing we wished existed: one place where a person can describe a problem in ordinary words — or simply speak it — and get back a plain-English explanation, the practical steps to take, the Act that applies, and the document they will need.

  • {{ kb_stats.topics }} legal topics, each with a summary, key points, a step-by-step procedure, the statutes that apply and FAQs.
  • {{ kb_stats.documents }} document templates with every blank marked, plus notes on stamp duty and registration.
  • {{ kb_stats.glossary }} glossary terms explaining the legal words used everywhere else.
  • {{ kb_stats.faqs }} answered FAQs and ten emergency quick-help cards.
  • A talking chatbot that listens, searches, answers and speaks.

How it was built

The whole system is deliberately simple. There is no TypeScript, no React, no build step and no external framework. Everything is either plain Python or plain browser code, so every line can be explained during a viva.

How the chatbot actually works

There is no magic and no pre-trained model in the offline engine. The steps are:

  1. Clean — the question is lower-cased, punctuation is stripped, and it is split into words.
  2. Stem — word endings are removed so “filing”, “filed” and “file” all match.
  3. Expand — everyday words are mapped to legal ones, so “my boss fired me” also searches for “termination”.
  4. Weigh — every word gets a TF-IDF score, so rare words like “gratuity” count far more than common ones like “law”.
  5. Match — cosine similarity compares the question vector against all {{ kb_stats.topics + kb_stats.documents }} indexed entries and picks the closest.
  6. Compose — the winning entry is turned into a structured answer: direct explanation, key points, steps, and the law.

An intent layer sits on top, so greetings, thanks, emergencies and requests for a document format are handled differently from an ordinary legal question.

Optional AI mode

If an API key is configured, the retrieved knowledge-base entries are passed to a Claude model which writes the final reply in its own words — a technique called Retrieval Augmented Generation. The model is instructed to use only the supplied material, so it cannot invent a section number or a deadline.

Honest limitations

  • The knowledge base is hand-written and simplified for learning; it is not a substitute for the bare Acts.
  • Statutes are amended frequently, and several provisions differ from State to State — especially stamp duty and tenancy rules.
  • The offline engine matches on words, so an unusual phrasing can still miss the right topic.
  • Voice input needs a Chromium-based browser and a microphone permission.
  • This is an academic project. It is not a law firm and it gives no legal advice.

What we would build next

  • Regional language support in both the text and the voice layers.
  • Semantic embeddings so the search understands meaning, not only words.
  • A lawyer directory and appointment booking.
  • Automatic filling of the templates from a guided question flow.
  • Live updates from official sources when an Act is amended.
